# Web UI 采集与恢复

## 默认策略

- 每个平台单标签、题目串行；平台之间可并行，但提交动作错峰。
- 默认全局交互间隔 30 秒、同平台间隔 120 秒；连续成功后的冷却频率由运行计划配置，不写死为规避风控。
- 每题新会话，不追问、不 regenerate；技术失败最多延迟重试一次。
- 验证码、登录失效、限流或平台不可用时停止对应平台，保留事件并等待用户恢复；不得绕过。

## 证据最低集合

- 完整回答文本；
- 初始回答区和可见来源截图、受控 DOM；
- 一次展开全部可见来源后的截图、受控 DOM；
- 来源卡：绑定 URL、可见标题/站点、锚文本或答案片段、locator；
- 引用候选与 rejected 原因；
- 问题原文、实际发送文本、平台可见文本和改写状态。

中断后从 `control/events.jsonl` 恢复，只对没有 `prompt_sent` 的单元提交新问题；已提交未捕获的单元优先恢复证据，不重复发送。

仓库内 `scripts/browser_evidence_collector.mjs` 提供 DeepSeek、豆包、千问、Kimi 和腾讯元宝的示例适配器。平台 UI 发生变化或接入其他平台时，应新增/更新独立适配器并记录版本，不能用全页面链接扫描代替可见来源卡解析。
